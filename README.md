# 衣合：使用与接入说明

## 直接使用

在线应用：[直接打开衣合](https://ycao51429-creator.github.io/yihe-style-compass/)（独立网页版，无需登录）。

此地址直接加载应用，不再跳转到 chatgpt.site。身材填写、偏好、搭配生成、收藏、导出和本地档案均在浏览器内运行；所需脚本与样式随网站一起发布，不依赖外部 CDN。

原 Sites 版本仍保留，但部分访客可能遇到其域名前的 Cloudflare 安全拦截；公开权限并不代表所有网络和浏览器都能访问。

0. 首页为“穿搭顾问”，可直接描述预算、场景、身材与避开项；“精选衣橱”支持商品详情、面料对比、收藏及试穿清单导出。进入“3D 试衣间”：切换四套服装，调整颜色、松量、身高和三围；可旋转、缩放并保存 PNG 图片。点击“导入我的档案”使用已填写的身材尺寸。缺少的尺寸使用示例值，超出模型范围的值会明确提示并限制在边界；原档案不会被修改。
1. 在“我的档案”填写身高、体重与可选的三围、脸型、发型。也可点击“试试示例”体验，示例不代表你的资料。
2. 选择整套预算、风格、场景与季节。
3. 生成三套方案，比较单品与计划花费，收藏或导出。
4. 在“附近好店”填写城市与商圈，或主动授权定位。
5. 在“使用说明”里选择是否将档案保存在当前浏览器；可随时清除。

照片只用于本地预览，不会上传。没有照片识别模型。预算为计划金额，原搭配卡插图为配色参考。新增的 3D 人物是可交互的款式与比例示意，不重建本人长相、不做布料物理仿真、不预测真实商品合身度。四套建模服装独立于规则生成的文字商品方案。

## 3D 试衣间

- 使用随站点打包的 Three.js 与 CC0 网格服装模型；模型文件从本站按需加载，不依赖第三方 3D CDN。首次进入试衣间约需下载 10 MB 模型数据。
- 支持工装外套与牛仔、衬衫与牛仔、连衣裙、卫衣与牛仔四套通用轮廓，以及正面 / 侧面 / 背面、拖动旋转、缩放、手动开启自动旋转。默认不自动播放。
- 参数范围：身高 140–200 cm、胸围 65–130 cm、腰围 50–125 cm、臀围 70–140 cm。当前使用示例身材 168 / 86 / 70 / 94，导入档案或拖动滑块后会明确显示来源。体重和照片不用于推算模型。
- 需要支持 WebGL 2 的浏览器。不支持或上下文丢失时显示说明，档案和搭配功能仍可使用。
- PNG 保存会包含“款式与比例示意”标注。关闭当前试衣页面会重置未保存的模型调整。
- `lib/retail-model.ts`：模型加载、姿态与材质；`public/models/SOURCES.md`：模型来源和许可；`components/fitting-room.tsx`：场景和交互；`components/fitting-room.css`：响应式界面。
- `npm test` 检查搭配服务约定与四套服装在不同体型下的几何完整性。

## 本轮新增：顾问与精选衣橱

- 顾问识别整套预算、场景、男女装方向、季节、厘米尺寸、公斤或斤及避开项，更新同一份档案和偏好，并可进入原有搭配流程。它是本地规则顾问，尚未连接开放式大模型；页面明确标明该状态。
- 精选库首批 6 件来自优衣库官方专题，核实日期 2026-11-01。品牌模特图通过原网址展示，图片范围和年份在详情中说明。系列图片不保证对应当前货号，未核实的纤维比例、实时价格和库存不补造。
- 支持搜索、分类、收藏、最多三件对比、文本清单导出；收藏和聊天只保留在当前页面。
- 小红书、抖音、百度和哔哩哔哩入口按商品名称与测评维度生成搜索词。它们是外部搜索入口，不是实时抓取结果；历史参考只概括可见索引，并明确日期及适用范围。
- 商品与照片出处见 `lib/shop-catalog.ts`，本轮来源记录见 `CATALOG-SOURCES.md`。品牌图片可能受第三方网络或防盗链影响，加载失败时提供原站链接。

## 完整联网版本所需接入

当前发布完成的是浏览器可用的顾问、选购与立体展示版本。要完成开放式资深销售式对话和实时跨站检索，需要额外部署服务端，使用所有者的模型服务账号与搜索账号；现有站点没有这些凭证。不能把模型密钥放进 GitHub Pages。

建议接入顺序：服务端模型接口（对话与明确授权的档案）→ 搜索接口（返回 URL、时间、货号匹配和摘要）→ 高德门店 → 商家授权 SKU/库存数据。小红书和抖音的公开网页可见范围有限，搜索摘要不等于完整笔记、评论或已观看的视频。上线时应只显示实际取得的内容。

现有 `lib/discovery.ts` 与 `app/api/discover/route.ts` 保留高德、Tavily、商家适配器。开放式模型对话接口尚未实现；其余适配器缺少生产账号，不能声称已完成真实服务联调。

## 开启完整的站内联网查询

GitHub Pages 版仅运行前端，不提供服务器接口。当前自动搜索、门店和库存按钮会明确提示使用外部搜索入口，不会尝试连接 chatgpt.site。若要启用站内真实查询，需要单独部署本仓库的服务端版本，并完成密钥配置和授权。不要将密钥放入 GitHub Pages 的前端构建。服务端使用以下配置：

| 服务端变量 | 用途 | 获取方式 |
| --- | --- | --- |
| `AMAP_WEB_KEY` | 地理编码、坐标转换、地区反查、附近服装店 | 在高德开放平台申请 Web 服务 Key，确认对应服务权限 |
| `TAVILY_API_KEY` | 网上穿搭参考检索 | 在 Tavily 申请搜索服务凭证 |
| `MERCHANT_DATA_URL` | 指定商家的评价和库存数据 | 商家或授权数据平台提供 HTTPS 接口 |
| `MERCHANT_API_TOKEN` | 商家接口鉴权 | 由商家或授权数据平台提供；服务不要求时可不填 |

密钥应通过部署平台的服务端环境变量管理功能录入，不要放入前端或公开文档。高德与搜索的适配器需要使用有效账号再进行真实联调；当前外部成功响应的自动化测试使用受控测试数据。

## 商家接口协议

软件以 GET 方式调用 `MERCHANT_DATA_URL`，追加查询参数 `amap_id=<高德门店ID>`。如配置令牌则发送 `Authorization: Bearer ...`。接口应返回下列 JSON；示例只说明格式，不是实际库存：

```json
{
  "store_id": "真实高德门店ID",
  "updated_at": "当前库存更新时间的ISO8601字符串",
  "source_url": "https://merchant.example/该门店的库存来源",
  "review": {
    "rating": 4.5,
    "count": 120,
    "source_url": "https://merchant.example/该门店的评价来源"
  },
  "inventory": [
    {
      "sku": "真实货号",
      "name": "商品名称",
      "size": "M",
      "color": "米白",
      "quantity": 3,
      "price": 199
    }
  ]
}
```

返回门店 ID 必须匹配请求。库存超过 15 分钟、更新时间无效或缺少 HTTPS 来源时，数量不作为现货展示。即使数据新鲜也不能保证用户到店时尚有库存；购买前应再次向门店确认。评分按 0—5 分解析，无来源则不展示。

本项目没有建立商家与高德 ID 的映射数据库，也没有采购数据服务。供应商需负责授权、门店匹配、SKU 数据准确性与同步。

## 源码运行

源码压缩包不包含密钥与 node_modules。安装 Node.js 22.13+ 和 npm 后，在解压目录执行：

```text
npm ci
npm run dev
```

按终端显示的本地网址访问。构建命令为 `npm run build`。本地开发密钥可放在不纳入版本控制的 `.dev.vars`，生产环境在托管平台配置。

源码使用 React、TypeScript、Vinext 和 Cloudflare Workers，保留 Sites 部署集成。更换托管平台时需要调整对应构建与运行配置。原站点标识由所有者管理，不应在新站复制复用。

## 验证范围

- 检查三套预算和分项总额一致，并在有效预算内。
- 检查季节、服装倾向、避开项、缺少服务配置、非法坐标与网络失败。
- 验证模拟服务结果不会将缺失评分或过期库存误报为真实数据。
- 实际浏览器检查电脑页面、手机页面、生成、收藏、导出、本地保存与清除。
- 未使用真实高德、Tavily 或商家生产凭证验证查询结果；没有验证真实用户的设备定位成功率。

公开上线前还需完成真实服务联调、服务配额与费用设置、用户与数据授权、隐私条款、商家合同及适用于目标运营模式的合规评估。

## 构建独立 GitHub Pages 版

```text
npm ci
npm run build:pages
```

结果写入 docs/。本仓库 Pages 从 main 分支的 /docs 发布。源码入口为 pages/main.tsx，与服务端版共享 React 页面、样式和推荐规则。lib/client-api.ts 在静态构建时返回明确的未接入提示，避免发送无效接口请求。修改源代码后需重新构建并提交 docs/。
